Masalah dan pengguna

Kasus: IMDB

Pitch

Orang tahu suasana film yang ingin ditonton, tapi jarang tahu judulnya. Pencarian biasa butuh judul atau genre yang persis. Asisten ini menerima cerita bebas ("film tentang balas dendam yang lambat tapi menegangkan"), lalu mencarikan film yang cocok dari 1.000 film terbaik IMDB dan menjelaskan alasannya dengan data: rating, metascore, sutradara, dan pemain.

Kenapa dataset ini cocok untuk agentic RAG

  • Teks untuk RAG: setiap film punya Overview satu paragraf, cocok untuk pencarian makna.
  • Kolom terstruktur untuk tool non-RAG: tahun, genre, rating, metascore, durasi, sutradara, pemain, gross. Kata Pak Herman, dataset ini cocok kalau ingin "punya banyak tools".
  • Overview pendek: 1 film = 1 vektor, tanpa chunking (bab 04).
  • Link poster: UI bisa menampilkan kartu film, sehingga demonya lebih menarik.

Aplikasi ini punya dua fase yang terpisah total. Fase offline dijalankan sekali: data dibersihkan, diubah jadi vektor, dan disimpan di Qdrant. Fase online berjalan setiap kali user bertanya: agent membaca pertanyaan, memilih tool, dan menyusun jawaban.

04

Fase offline

Ingestion ke Qdrant

Langkah

  1. Load + bersihkan dengan pandas: ubah Runtime "142 min" jadi angka, Gross "28,341,469" jadi angka, isi nilai kosong.
  2. Susun teks yang di-embed: judul. genre. overview. Sutradara dan pemain tidak di-embed, karena pertanyaan "film Nolan" lebih tepat dijawab lewat filter persis di rank_movies daripada lewat kemiripan makna. Angka disimpan di payload.
  3. Chunking: tidak perlu. Overview terpanjang 313 karakter (56 kata), jauh di bawah batas input model embedding. Satu film = satu point. Alasan ini perlu dijelaskan di video, karena Pak Herman menyebut chunking "kalau butuh".
  4. Bungkus jadi Document LangChain: page_content = teks yang di-embed, metadata = semua kolom lain. Kata Pak Herman, yang diubah ke vektor hanya page_content; metadata ikut tersimpan sebagai payload tapi tidak di-embed.
  5. Embed + upload dengan satu panggilan QdrantVectorStore.from_documents: membuat collection (ukuran otomatis 1536), meng-embed, dan meng-upload sekaligus. Pola ini persis notebook Sesi 12.
  6. Payload index untuk kolom yang difilter (metadata.genres, metadata.year). Ini tambahan di luar kelas; dengan 1.000 film tidak wajib, tapi praktik yang baik.

Kode inti · scripts/ingest.py (pola Sesi 12 Bab 6B)

def build_documents() -> tuple[list[Document], list[int]]:
    documents, ids = [], []
    for movie in to_records(load_movies()):        # data.py: satu sumber data
        text = f"{movie['title']}. {', '.join(movie['genres'])}. {movie['overview']}"
        documents.append(Document(page_content=text, metadata=movie))  # text di-embed, metadata = payload
        ids.append(movie["id"])                     # id tetap: ingest ulang menimpa, bukan menggandakan
    return documents, ids

QdrantVectorStore.from_documents(
    documents, get_embeddings(), ids=ids,
    url=url, api_key=api_key, prefer_grpc=True,
    collection_name=collection, batch_size=100,
    force_recreate=True,                           # collection dibuat ulang bersih
)

RAG tool · app/tools.py (pola kelas Sesi 14 Bab 7, ditambah filter)

Genre = Literal[tuple(all_genres())]               # 21 nilai persis dari dataset → enum di skema tool

@lru_cache(maxsize=1)
def _vector_store() -> QdrantVectorStore:          # sambung sekali, saat pertama dipakai
    return QdrantVectorStore.from_existing_collection(
        embedding=get_embeddings(), collection_name=env("QDRANT_COLLECTION"),
        url=env("QDRANT_URL"), api_key=env("QDRANT_API_KEY"),
    )

@tool(parse_docstring=True)
def search_movies(query: str, genre: Genre | None = None,
                  year_from: int | None = None, year_to: int | None = None) -> str:
    """Find movies by plot, theme, or mood among the IMDB top 1,000 movies (semantic search).

    Use this when the user describes what they want to watch. Do not use it to find a movie
    or a movie series by title; use get_movie_details for that.

    Args:
        query: Short description of the wanted plot or mood, written in English.
        genre: Only return movies that have this genre. Leave empty unless the user names a genre.
        ...
    """
    conditions = []
    if genre:      # LangChain menyimpan metadata di bawah kunci "metadata"
        conditions.append(models.FieldCondition(key="metadata.genres", match=models.MatchValue(value=genre)))
    if year_from or year_to:
        conditions.append(models.FieldCondition(key="metadata.year",
                                                range=models.Range(gte=year_from, lte=year_to)))

    docs = _vector_store().similarity_search(
        query, k=5, filter=models.Filter(must=conditions) if conditions else None,
    )
    movies = [{field: doc.metadata[field] for field in FIELDS_FOR_LLM} for doc in docs]
    return json.dumps({"movies": movies}, ensure_ascii=False)   # tanpa poster: hemat token (K25)

Kelas memakai similarity_search(query, k=10) tanpa filter. Dengan filter payload (filtered vector search), makna dicari lewat vektor, sedangkan syarat pasti (genre, tahun) lewat filter. Bukti: tanpa filter, 3 dari 5 hasil "thriller 90-an" bukan film 90-an (K04). Filter hanya dipasang kalau user menyebutnya, supaya LLM tidak menebak genre (K27).

Agent: loop ReAct

Cara kerja ReAct

Reason + Act: LLM berpikir, memanggil tool, membaca hasilnya, lalu memutuskan lagi, sampai bisa menjawab tanpa tool.

flowchart TD
  Q["pesan user"] --> M["LLM + daftar tool"]
  M -->|"ada tool_call"| X["jalankan tool"]
  X --> M
  M -->|"tidak ada tool_call"| R["jawaban final"]

Kode inti · app/agent.py (lengkap)

from langchain.agents import create_agent
from langfuse import get_client
from langfuse.langchain import CallbackHandler

PROMPT_NAME = "movie-agent-system"   # dibuat lewat UI Langfuse, label "production"

@lru_cache(maxsize=1)                 # dibuat sekali, saat pertanyaan pertama (K24)
def get_agent():
    system_prompt = get_client().get_prompt(PROMPT_NAME).compile()
    return create_agent(model=get_llm(), tools=TOOLS, system_prompt=system_prompt)

def run_agent(messages: list[dict], session_id: str) -> list:
    result = get_agent().invoke(
        {"messages": messages},          # seluruh riwayat, bukan pesan terakhir saja
        config={
            "callbacks": [CallbackHandler()],              # trace ke Langfuse
            "metadata": {"langfuse_session_id": session_id},
        },
    )
    return result["messages"][len(messages):]   # hanya pesan baru dari run ini

Observability

Langfuse: prompt dan trace

1 · Prompt management

  • System prompt agent bernama movie-agent-system, label production, dibuat lewat UI Langfuse (klarifikasi 22 Okt). Kode hanya memanggil get_prompt(nama).compile().
  • Mengganti prompt tidak perlu deploy ulang: buat versi baru, centang label production, dan app di Streamlit Cloud langsung memakainya.
  • Ditulis dalam bahasa Inggris, satu bahasa dengan docstring tool, data, dan query pencarian, tapi menjawab dalam bahasa user (K26).
  • Docstring tool tetap di kode karena merupakan bagian dari definisi fungsi.

2 · Tracing

  • CallbackHandler mengirim setiap run agent ke Langfuse: setiap pemanggilan LLM, setiap tool call beserta argumen dan hasil, token, latensi, dan biaya.
  • Trace dikaitkan ke session id Streamlit supaya satu percakapan terlihat utuh. Session id dikirim lewat config["metadata"]["langfuse_session_id"], bukan argumen CallbackHandler(...) seperti di slide 27, karena handler versi baru tidak menerima argumen (K02).
  • Region EU: LANGFUSE_HOST=https://cloud.langfuse.com. Kata Pak Herman, host "sering lupa".
  • Saat demo video: tunjukkan satu session (contohnya e2e-prompt-v2-23okt) setelah bertanya di Streamlit.

08

Front end

Streamlit: chat, tool call, usage

Tiga hal yang disebut Pak Herman harus ada di contoh Streamlit: chat history, tool call, dan usage detail.

Susunan layar (yang sudah jalan)

  • Area chat: st.chat_message untuk setiap pesan, disimpan di st.session_state.chat supaya tidak hilang saat Streamlit rerun.
  • Kartu poster di bawah jawaban: hanya film yang disebut di jawaban, maksimal 5, urut sesuai hasil tool. Poster 300 px diambil dari data.py lewat id, tidak lewat LLM.
  • Expander "🔧 N tool call": nama tool, argumen, dan judul hasilnya.
  • Baris usage: token input dan output, dijumlahkan dari semua panggilan LLM dalam satu pertanyaan.

Contoh nyata: "film tentang membunuh suami dan menghilang" → 1 tool call, 3 poster (Gone Girl, Kahaani, Dial M for Murder), 2.641 token input · 164 output.

for message in st.session_state.chat:      # chat history
    with st.chat_message(message["role"]):
        st.markdown(message["content"])
        if message.get("details"):
            show_details(message["details"])  # poster + tool call + usage

if question := st.chat_input("Misalnya: thriller tahun 90-an yang bikin tegang"):
    st.session_state.chat.append({"role": "user", "content": question})
    history = [{"role": m["role"], "content": m["content"]} for m in st.session_state.chat]
    new_messages = run_agent(history, st.session_state.session_id)
    answer = new_messages[-1].content
    details = summarize_run(new_messages, answer)   # tool call, id poster, token
    st.session_state.chat.append({"role": "assistant", "content": answer, "details": details})

Pelajaran dari main.py kelas (catatan Sesi 14 Bab 7)

  • Agent kelas tidak ingat percakapan: riwayat disimpan di session_state hanya untuk ditampilkan, sedangkan yang dikirim ke agent hanya pesan terakhir. Capstone mengirim seluruh riwayat supaya pertanyaan lanjutan ("yang kedua tadi siapa sutradaranya?") bisa dijawab.
  • Role disimpan sebagai user/assistant, bukan "Human"/"AI", supaya riwayat bisa langsung dikirim ulang ke agent.
  • Tidak memakai except: kosong untuk membaca .env, karena salah ketik nama variabel jadi tidak terlihat penyebabnya.

Poster: dua jebakan yang ditemukan saat uji

  • Judul di dalam judul. "Star Wars" ada di dalam "Star Wars: Episode V - …". Karena itu judul terpanjang dicocokkan dulu, lalu dihapus dari teks jawaban, supaya judul yang lebih pendek tidak ikut cocok.
  • Urutan dari teks itu rapuh. Kalimat pembuka "Tiga Star Wars dengan rating tertinggi…" sempat membuat poster film 1977 tampil paling depan. Sekarang urutan poster mengikuti hasil tool (peringkat atau relevansi).

Yang dicek dan ternyata aman

  • Riwayat chat membengkak? Yang disimpan hanya teks user dan jawaban akhir, bukan output tool, jadi tiap giliran hanya menambah ratusan token. Akibatnya, pertanyaan lanjutan harus memanggil tool lagi, dan ini diatur di prompt v2.
  • Agent dibangun ulang tiap klik? main.py kelas begitu, karena semua kode ada di file Streamlit. Di struktur kita get_agent() memakai @lru_cache, jadi agent dibuat sekali per proses saat pertanyaan pertama, bukan saat di-import (K24).
  • Secret di Streamlit Cloud: secret tingkat atas juga tersedia sebagai variabel lingkungan, jadi os.getenv di config.py bekerja di laptop maupun di cloud.

Keputusan klarifikasi Pak Herman · 22 Okt

  • Qdrant bebas caranya; filter metadata boleh; isinya harus bisa dilihat penilai.
  • Langfuse: versi yang jalan; hanya system prompt, lewat UI; trace per pertanyaan dan per session.
  • Agent ingat percakapan per sesi, dengan cara yang ringan.
  • Chat history, tool call, dan usage wajib semua. Deploy Streamlit wajib. Dataset boleh publik.

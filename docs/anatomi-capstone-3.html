Kasus: IMDB

Kata Pak Herman di kelas: "Salah satunya aja, gak perlu pakai dua-duanya. Tapi kalau pengen pakai dua-duanya gak apa-apa, cuman bakal lebih kompleks dan gak nyambung. Satunya HR, satunya film." Memakai keduanya tidak menambah syarat yang terpenuhi, hanya menambah kerja dan membuat pitch ke "C-level" jadi tidak fokus. Rekomendasi: pilih satu.

Opsi A · IMDB Movie

Pitch: asisten rekomendasi film. User cukup menceritakan selera ("film tentang balas dendam yang lambat tapi menegangkan"), agent mencarikan dan menjelaskan.

  • Kolom terstruktur banyak (tahun, genre, rating, metascore, durasi, sutradara, pemain, gross), jadi mudah membuat tool non-RAG: statistik, filter, perbandingan.
  • Kata Pak Herman: cocok kalau ingin "punya banyak tools".
  • Overview pendek (satu paragraf), jadi chunking hampir tidak perlu: 1 film = 1 vektor.
  • Ada link poster, sehingga UI Streamlit bisa tampil bagus (nilai tambah UI).

Opsi B · Resume (HR)

Pitch: asisten rekruter. HR menulis kebutuhan posisi, agent mencari kandidat yang cocok, merangkum, dan menjawab pertanyaan seperti ekspektasi gaji.

  • Cerita bisnisnya kuat untuk presentasi: menghemat waktu screening CV.
  • Teks CV panjang, jadi chunking benar-benar dibutuhkan dan konsep RAG lebih terlihat.
  • Kata Pak Herman: "lebih menantang". Contoh repo tutor justru memakai kasus ini (search_resume), jadi referensinya ada tapi risiko terlihat "mirip contoh" lebih besar.
  • Tool filter (kota, kategori, gaji) bergantung pada kolom terstruktur yang belum diketahui.

Keputusan · 21 Oktober 2026

IMDB dipilih. Kolom terstrukturnya memberi tool non-RAG yang jelas, overview-nya cukup pendek sehingga satu film cukup jadi satu vektor, dan poster membuat UI mudah dibuat menarik. Perbandingan dengan Resume di atas disimpan sebagai alasan pemilihan, untuk bagian "tujuan" di video.

Arsitektur

Cara kerja dari 4 dimensi

Aplikasi ini punya dua fase yang terpisah total. Fase offline dijalankan sekali: data dibersihkan, diubah jadi vektor, dan disimpan di Qdrant. Fase online berjalan setiap kali user bertanya: agent membaca pertanyaan, memilih tool, dan menyusun jawaban.

Dimensi 1 · Data flow: offline vs online

    CSV["dataset.csv"] --> CLEAN["ingest.py: bersihkan kolom, susun teks"]
    CLEAN --> CHUNK["chunking (kalau teks panjang)"]
    CHUNK --> EMB["embedding API"]
    EMB --> QD[("Qdrant Cloud: collection + payload")]
  end
  subgraph ON["Fase online: tiap pertanyaan"]
    U["User di Streamlit"] --> AG["agent.py: ReAct agent"]
    LFP[("Langfuse: system prompt")] --> AG
    AG --> T1["RAG tool"]
    AG --> T2["tool non-RAG"]
    T1 --> QD
    T2 --> DF[("data terstruktur: pandas/SQLite")]
    AG --> ANS["jawaban + tool call + usage"]
    ANS --> U
    AG -.trace.-> LFT[("Langfuse: trace")]
  end

Fase offline bisa ditulis sebagai script atau notebook (.ipynb); Pak Herman membolehkan notebook khusus untuk bagian ini.

04

Fase offline

Ingestion ke Qdrant

Langkah

  1. Load + bersihkan dengan pandas: ubah Runtime "142 min" jadi angka, Gross "28,341,469" jadi angka, isi nilai kosong.
  2. Susun teks yang di-embed: gabungkan kolom yang bermakna semantik (judul, genre, overview, sutradara, pemain) jadi satu string. Angka tidak perlu di-embed; angka disimpan di payload.
  3. Chunking: tidak perlu. Overview terpanjang 313 karakter (56 kata), jauh di bawah batas input model embedding. Satu film = satu point. Alasan ini perlu dijelaskan di video, karena Pak Herman menyebut chunking "kalau butuh".
  4. Embedding per batch (misalnya 100 teks per request) supaya cepat dan tidak kena rate limit.
  5. Upsert ke collection Qdrant: vector + payload (semua kolom asli).
  6. Payload index untuk kolom yang akan difilter (genre, tahun, rating; atau kategori, kota).

Kode inti (sketsa)

from qdrant_client import QdrantClient, models

qdrant = QdrantClient(url=QDRANT_URL, api_key=QDRANT_API_KEY)

qdrant.create_collection(
    collection_name="movies",
    vectors_config=models.VectorParams(
        size=1536,                      # = dimensi model embedding
        distance=models.Distance.COSINE, # Sesi 01: cosine similarity
    ),
)

qdrant.upsert(
    collection_name="movies",
    points=[
        models.PointStruct(id=i, vector=vec, payload=row)
        for i, (vec, row) in enumerate(zip(vectors, rows))
    ],
)

qdrant.create_payload_index(
    "movies", field_name="genres",
    field_schema=models.PayloadSchemaType.KEYWORD,
)

  • Sutradara terbanyak: Alfred Hitchcock 14, Steven Spielberg 13, Hayao Miyazaki 11, Martin Scorsese 10, Akira Kurosawa 10.

Bentuk RAG tool (sketsa, kasus IMDB)

from langchain_core.tools import tool

@tool
def search_movies(query: str, genre: str | None = None,
                  min_rating: float | None = None, limit: int = 5) -> str:
    """Cari film berdasarkan deskripsi cerita, suasana, atau tema.
    Pakai ini kalau user menjelaskan selera, bukan menyebut judul."""
    must = []
    if genre:
        must.append(models.FieldCondition(key="genres", match=models.MatchValue(value=genre)))
    if min_rating:
        must.append(models.FieldCondition(key="rating", range=models.Range(gte=min_rating)))

    hits = qdrant.query_points(
        collection_name="movies",
        query=embed(query),                                 # vektor pertanyaan
        query_filter=models.Filter(must=must) if must else None,
        limit=limit,
    ).points
    return format_hits(hits)                               # teks ringkas untuk LLM

Gabungan vektor + filter payload disebut filtered vector search: makna dicari lewat vektor, syarat pasti (genre, rating) lewat filter.

Orkestrasi

Agent: loop ReAct

Cara kerja ReAct

Reason + Act: LLM berpikir, memanggil tool, membaca hasilnya, lalu memutuskan lagi, sampai bisa menjawab tanpa tool.

flowchart TD
  Q["pesan user"] --> M["LLM + daftar tool"]
  M -->|"ada tool_call"| X["jalankan tool"]
  X --> M
  M -->|"tidak ada tool_call"| R["jawaban final"]

Kode inti (sketsa)

from langchain.agents import create_agent
from langfuse import get_client
from langfuse.langchain import CallbackHandler

langfuse = get_client()
system_prompt = langfuse.get_prompt("movie-agent-system").compile()

agent = create_agent(
    model=llm,
    tools=[search_movies, get_movie_detail, movie_stats, top_movies],
    system_prompt=system_prompt,
)

def run_agent(messages: list) -> dict:
    return agent.invoke(
        {"messages": messages},
        config={"callbacks": [CallbackHandler()]},  # trace ke Langfuse
    )

07

Observability

Langfuse: prompt dan trace

1 · Prompt management

  • System prompt agent dibuat di Langfuse dengan nama tetap, misalnya movie-agent-system, label production.
  • Kode hanya memanggil get_prompt(nama). Mengganti prompt tidak perlu deploy ulang, dan setiap versi tercatat.
  • Prompt lain (misalnya untuk tool score_match atau reranker berbasis LLM) juga disimpan di Langfuse. Syaratnya: tidak ada prompt hardcode di repo.
  • Isi prompt: role, daftar tool dan kapan dipakai, aturan jawaban (bahasa, format, jangan mengarang di luar hasil tool). Struktur dari Sesi 08.

2 · Tracing

  • CallbackHandler mengirim setiap run agent ke Langfuse: pesan, setiap pemanggilan LLM, setiap tool call beserta argumen dan hasil, token, latensi, dan biaya.
  • Trace dikaitkan ke session id Streamlit supaya satu percakapan terlihat utuh.
  • Saat demo video: tunjukkan satu trace di dashboard Langfuse setelah bertanya di Streamlit.

Prompt caching: perlu atau tidak?

Dari tanya-jawab di kelas: caching Anthropic baru aktif kalau prompt yang di-cache melewati batas minimum token (1.024 sampai 4.096 tergantung model), dan yang cocok di-cache hanya system prompt karena isinya selalu sama. System prompt capstone kemungkinan jauh di bawah batas itu, jadi caching tidak perlu untuk capstone ini.

08

Front end

Streamlit: chat, tool call, usage

Tiga hal yang disebut Pak Herman harus ada di contoh Streamlit: chat history, tool call, dan usage detail.

Susunan layar

  • Sidebar: nama aplikasi, contoh pertanyaan yang bisa diklik, tombol reset percakapan, ringkasan token dan biaya sesi.
  • Area chat: st.chat_message untuk setiap pesan, disimpan di st.session_state.messages supaya tidak hilang saat Streamlit rerun.
  • Di bawah tiap jawaban: st.expander("Tool calls") berisi nama tool, argumen, dan cuplikan hasil; lalu baris kecil token input/output.
  • Nilai tambah IMDB: kartu film dengan poster dari Poster_Link (st.image).

Kode inti (sketsa)

import streamlit as st
from app.agent import run_agent

if "messages" not in st.session_state:
    st.session_state.messages = []

for m in st.session_state.messages:          # chat history
    st.chat_message(m["role"]).write(m["content"])

if q := st.chat_input("Ceritakan film yang kamu suka..."):
    st.session_state.messages.append({"role": "user", "content": q})
    result = run_agent(st.session_state.messages)
    final = result["messages"][-1]
